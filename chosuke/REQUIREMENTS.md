# 日程調整ツール 要件定義書

Oct 3, 2026 · @まさひろ

## 1. 概要

tappyと同じ操作感の日程調整ツールを自作し、独自ドメイン＋エックスサーバーで公開する。tappyとの違いは、回答を「⭕️対面OK／💻オンラインのみ／△」の3種類から選べることの1点に絞る。

| 項目 | 内容 |
| --- | --- |
| Who | 主催者（まさひろ）がイベントを作成し、参加者（ログイン不要）が回答する |
| What | 日付×時間のマス目に4種類の記号で回答し、全員分を集計表で確認する |
| When | 複数人の予定を合わせるたびに、イベントを作成してURLを共有する |
| Where | 独自ドメイン配下のフォルダ（例：`https://<ドメイン>/chousei/`） |
| Why | tappyは⭕️／❌の2択で、△や対面／オンラインの区別ができないため |
| How | HTML＋JavaScript（画面）、PHP（保存処理）、SQLite（データ保存） |

**対象外（今回は作らない）**

- ログイン・アカウント機能
- Googleカレンダーなど外部カレンダーとの連携
- 確定日時の通知（メール・LINE）

## 2. 前提・技術構成

フレームワークは使わず、エックスサーバーにファイルをアップロードするだけで動く構成にする。データベースはファイル1つで動くSQLiteを使い、サーバー側の初期設定を不要にする。

| 区分 | 採用技術 | 備考 |
| --- | --- | --- |
| サーバー | エックスサーバー | 独自ドメイン設定済み |
| サーバー処理 | PHP 8.x | エックスサーバーの標準機能 |
| データ保存 | SQLite（PDO経由） | DBファイルは公開ディレクトリの外に置く |
| 画面 | HTML＋CSS＋素のJavaScript | ビルド工程なし |
| 開発環境 | VSCode＋Claude Code | ローカルは `php -S` で動作確認 |

**ディレクトリ構成（案）**

```
chousei/
├── index.html        … イベント作成画面
├── event.html        … 回答＋集計画面（?id=イベントID）
├── admin.html        … 管理画面（?token=管理トークン）
├── assets/
│   ├── style.css
│   └── app.js
├── api/
│   ├── event.php     … イベントの作成・取得・編集・削除
│   └── answer.php    … 回答の保存・取得
└── .htaccess         … api以外への直接アクセス制御など

（公開ディレクトリの外）
chousei_data/
└── chousei.sqlite    … データベースファイル
```

- 未決事項：設置するドメインとフォルダ名（`chousei/` は仮）

## 3. 画面構成とUI/UX

UI/UXはtappyに合わせ、「横に日付、縦に時間のマス目をタップして回答する」操作をそのまま再現する。スマホ（縦持ち・幅375px前後）を基準に設計し、PCでも崩れないようにする。

| 画面 | URL | 使う人 | 主な内容 |
| --- | --- | --- | --- |
| イベント作成 | `/chousei/` | 主催者 | タイトル・候補日・時間帯・刻みを入力して作成 |
| 作成完了 | 作成後に表示 | 主催者 | 参加者用URLと管理用URLを表示（コピーボタン付き） |
| 回答＋集計 | `/chousei/event.html?id=…` | 参加者 | マス目で回答し、下に全員分の集計表を表示 |
| 管理 | `/chousei/admin.html?token=…` | 主催者 | イベントの編集・削除、回答の削除 |

**マス目（回答グリッド）の仕様**

- 列＝候補日（上部に「10/5(日)」形式で表示）、行＝時間（左端に「18:00」形式で表示）
- マスをタップするたびに「空欄 → ⭕️ → 💻 → △ → 空欄」の順で切り替わる
- 記号ごとに背景色を変えて、離れて見ても区別できるようにする
- 一括変更：PC（マウス）は押してなぞる。スマホは約0.3秒長押し（軽く振動）してからなぞると、なぞった範囲のマスを最初のマスと同じ記号に一括変更できる。長押しせずになぞった場合は表がスクロールし、動かさずに離した場合はタップ（1マス切り替え）として扱う
- 候補日が多くて横にはみ出す場合は、表だけ横スクロールにし、日付行と時間列は固定表示する
- 画面下部に記号の凡例（⭕️対面OK／💻オンラインのみ／△微妙）を常に表示する
- タップできるマスは最低44×44px（スマホで押し間違えない大きさ）

**集計表の仕様**

- 回答グリッドと同じ形の表で、各マスに「⭕️3 💻1 △1」のように人数を表示する
- 行ける人数（⭕️＋💻）の割合に応じて、薄い緑→濃い緑の3段階で背景色を付ける（0人は無色）
- 全員が⭕️または💻のマスを最も濃い色で強調し、⭕️のみのマスと💻を含むマスは色を分ける
- マスをタップすると、そのマスに誰が何と回答したかを一覧表示する
- 回答者の名前一覧を表示し、名前をタップするとその人の回答を開いて修正できる
- 未決事項：tappyの画面のスクリーンショットを開発時に参照用として用意する（細かい見た目を合わせるため）

## 4. 機能要件

機能は「イベント作成」「回答」「集計表示」「管理」の4つ。編集・削除は管理用URLを持つ人だけが行える。

**4-1. イベント作成（主催者）**

| 入力項目 | 形式 | 必須 | ルール |
| --- | --- | --- | --- |
| タイトル | テキスト | ○ | 50文字以内 |
| メモ | テキスト | － | 200文字以内（場所・目的など） |
| 候補日 | カレンダーから複数選択 | ○ | 1〜31日 |
| 開始時刻・終了時刻 | 時刻選択 | ○ | 開始＜終了 |
| 時間の刻み | 15分／30分／1時間 から選択 | ○ | 初期値は30分 |

- 作成すると、参加者用URL（イベントID付き）と管理用URL（管理トークン付き）を発行する
- 管理用URLは作成完了画面でのみ表示し、「主催者以外に共有しないでください」と注意書きを出す

**4-2. 回答（参加者）**

- 名前（20文字以内）を入力し、マス目で回答して「保存」を押す
- 回答は4状態：空欄（未回答）／⭕️対面OK／💻オンラインのみ／△微妙
- 同じ名前で再度保存すると上書きにならないよう、回答ごとに編集用キーを発行し、端末のブラウザに保存する。その端末からは自分の回答を修正できる
- 別端末から修正したい場合は、回答者一覧から自分の名前を選んで修正できる（簡易運用のため認証はしない）

**4-3. 集計表示**

- 保存後、集計表に即時反映する（ページ再読み込みなしで更新）
- 第3章の集計表の仕様に従って表示する

**4-4. 管理（主催者のみ）**

- 管理用URLを開いた場合だけ、以下の操作を表示する
- イベント情報（タイトル・メモ・候補日・時間帯・刻み）の編集
- 候補日・時間帯を減らした場合、該当マスの回答は削除する（削除前に確認ダイアログを出す）
- 刻みの変更は回答が0件のときだけ許可する
- 個別の回答の削除
- イベント全体の削除（確認ダイアログ必須）
- 参加者用URLからは、編集・削除の操作は一切表示しない

## 5. データ設計

テーブルは「events」と「answers」の2つ。マスごとの回答はJSONでまとめて1行に保存し、構造を単純にする。

**events（イベント）**

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | TEXT（主キー） | 参加者用URLに使うランダム文字列（12文字） |
| admin\_token | TEXT | 管理用URLに使うランダム文字列（32文字、推測不可能なもの） |
| title | TEXT | タイトル |
| memo | TEXT | メモ |
| dates | TEXT（JSON） | 候補日の配列 例：`["2026-10-10","2026-10-11"]` |
| start\_time | TEXT | 例：`18:00` |
| end\_time | TEXT | 例：`22:00` |
| slot\_minutes | INTEGER | 15／30／60 |
| created\_at | TEXT | 作成日時 |
| updated\_at | TEXT | 更新日時 |

**answers（回答）**

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | INTEGER（主キー） | 自動採番 |
| event\_id | TEXT | events.id |
| name | TEXT | 回答者名 |
| edit\_key | TEXT | 回答修正用のランダム文字列（ブラウザに保存） |
| slots | TEXT（JSON） | マスごとの回答 例：`{"2026-10-10_18:00":"ok","2026-10-10_18:30":"online"}` |
| created\_at | TEXT | 作成日時 |
| updated\_at | TEXT | 更新日時 |

- 回答値は `ok`（⭕️）／`online`（💻）／`maybe`（△）の3種類。空欄はキー自体を持たない
- マスのキーは「日付\_開始時刻」の形式で統一する

## 6. API設計

画面のJavaScriptからPHPへJSONで送受信する。管理系の操作はすべて `admin_token` が一致したときだけ実行する。

| 操作 | メソッド・URL | 送るもの | 返すもの | 権限 |
| --- | --- | --- | --- | --- |
| イベント作成 | POST `api/event.php` | タイトル・メモ・候補日・時間帯・刻み | id、admin\_token | 誰でも |
| イベント取得 | GET `api/event.php?id=…` | － | イベント情報（admin\_tokenは含めない） | 誰でも |
| イベント編集 | PUT `api/event.php?token=…` | 変更後のイベント情報 | 更新後のイベント情報 | 管理者 |
| イベント削除 | DELETE `api/event.php?token=…` | － | 成否 | 管理者 |
| 回答一覧取得 | GET `api/answer.php?event_id=…` | － | 回答一覧（edit\_keyは含めない） | 誰でも |
| 回答保存（新規） | POST `api/answer.php` | event\_id・名前・slots | 回答id、edit\_key | 誰でも |
| 回答保存（修正） | PUT `api/answer.php?id=…` | 名前・slots（＋edit\_key） | 更新後の回答 | 誰でも（第4章4-2参照） |
| 回答削除 | DELETE `api/answer.php?id=…&token=…` | － | 成否 | 管理者 |

- エックスサーバーでPUT／DELETEが通らない場合は、すべてPOSTにして `action` パラメータで操作を分ける
- エラー時はHTTPステータスと `{"error":"メッセージ"}` を返す
- 集計表の即時反映は、保存後に回答一覧を再取得する方式でよい（リアルタイム通信は不要）

## 7. 非機能要件

個人利用の小規模ツールとして、最低限のセキュリティとスマホでの快適さを優先する。

**セキュリティ**

- SQLはすべてプリペアドステートメントで実行する（SQLインジェクション対策）
- 名前・タイトル・メモは表示時にエスケープする（XSS対策）
- IDとトークンは `random_bytes()` で生成する
- SQLiteファイルは公開ディレクトリの外に置き、URLから直接ダウンロードできないようにする
- 検索エンジンに載らないよう `noindex` を付ける
- 同じIPからの連続作成を簡易的に制限する（例：1分に10件まで）

**パフォーマンス・規模**

- 想定規模：1イベントあたり回答者30人以下、マス目500個以下
- 最大マス数を超える作成は弾く（例：31日×1日分の15分刻み＝2,976マスは不可）

**対応環境**

- iPhone（Safari）、Android（Chrome）、PCのChrome・Safari・Edgeの最新版
- LINEアプリ内ブラウザで開いても操作できること
- 表示は日本語のみ

**データ保持**

- 最終候補日から90日経過したイベントは自動削除する（cronまたはアクセス時に判定）

## 8. Claude Codeでの進め方

この要件定義書をMarkdownで書き出してプロジェクト直下に `REQUIREMENTS.md` として置き、Claude Codeにフェーズごとに実装させる。各フェーズの完了時に動作確認し、承認してから次へ進む。

1. **土台**：ディレクトリ構成、SQLiteの初期化処理、DB接続の共通処理
2. **イベント作成**：作成画面と `api/event.php`（作成・取得）、作成完了画面
3. **回答グリッド**：マス目の表示とタップ切り替え、なぞり操作、横スクロール時の固定表示
4. **回答保存**：`api/answer.php`（保存・修正・一覧取得）、edit\_keyのブラウザ保存
5. **集計表**：人数表示、全員OK枠の強調、マスのタップで回答者一覧
6. **管理画面**：イベント編集・削除、回答削除
7. **仕上げ**：セキュリティ項目の確認、スマホ実機（LINE内ブラウザ含む）での確認、エックスサーバーへのアップロード

**Claude Codeへの最初の指示（例）**

> `REQUIREMENTS.md` を読んで、フェーズ1だけ実装してください。実装前に作るファイルと方針を説明し、私の承認を得てから書き始めてください。各ファイルを新規作成するのか、既存ファイルに追記・置換するのかを明記してください。
